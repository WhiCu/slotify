# Отчёт: Развёртывание приложения Slotify в Kubernetes (Minikube)

## 1. Описание приложения

**Slotify** — клиент-серверное веб-приложение для бронирования рабочих пространств (переговорных комнат и рабочих мест). 

Пользователи могут просматривать доступные пространства, выбирать дату и временные слоты, создавать и отменять бронирования. Администраторы управляют пространствами и пользователями. В системе используются слоты длительностью 5 минут (288 слотов в сутках), а согласованность расписания обеспечивается ограничениями СУБД.

Архитектура состоит из трёх основных компонентов:
- **Frontend** — одностраничный веб-интерфейс (SPA), раздаваемый веб-сервером Nginx.
- **Backend** — REST API сервис на Go, реализующий бизнес-логику, авторизацию и миграции.
- **PostgreSQL** — реляционная база данных для персистентного хранения пространств, пользователей и бронирований.

## 2. Какие абстракции Kubernetes использованы для запуска

| Объект | Имя | Назначение |
|---|---|---|
| Namespace | slotify | изоляция проекта |
| Secret | slotify-db | переменные для образа Postgres (`POSTGRES_*`) |
| Secret | slotify-app | переменные приложения (`APP_*`) |
| StatefulSet | postgres | база данных с постоянным диском |
| PersistentVolumeClaim |   | создаётся автоматически из `volumeClaimTemplates` |
| Service | postgres | стабильное имя базы внутри кластера |
| Deployment | slotify-backend | 1–3 реплики API |
| Service | slotify-backend | внутренний доступ к API |
| Deployment | slotify-frontend | nginx с index.html |
| Service | slotify-frontend | внутренний доступ к фронтенду |
| Middleware, IngressRoute | slotify | маршрутизация Traefik на `slotify.local` |

## 3. Как сервисы приложения взаимодействуют между собой

Сетевое взаимодействие компонентов организовано следующим образом:

1. **Входная точка и маршрутизация (Traefik Ingress):**
   Пользователь обращается в браузере по адресу `http://slotify.local`. Запрос попадает в кластер через Ingress-контроллер Traefik, правила для которого заданы в манифесте `IngressRoute`.

2. **Загрузка пользовательского интерфейса (Frontend):**
   Запросы к корню сайта Traefik перенаправляет на Service `slotify-frontend:80`. Сервис распределяет трафик на поды с Nginx, который отдаёт статический файл `index.html`.

3. **Обработка API-запросов (Backend):**
   При действиях пользователя в интерфейсе браузер отправляет HTTP-запросы по пути `/api/...`.
   - Traefik перехватывает запросы по правилу `PathPrefix('/api/')`.
   - С помощью middleware `strip-api` префикс `/api` отсекается, приводя путь к стандартному виду эндпоинтов бэкенда (например, `/api/spaces` $\rightarrow$ `/spaces`).
   - Далее запрос отправляется на Service `slotify-backend:8080`, который балансирует нагрузку между запущенными репликами бэкенда.

4. **Работа с базой данных (PostgreSQL):**
   Бэкенд выполняет бизнес-логику и обращается к базе данных по внутрикластерному имени сервиса `postgres:5432`. Сетевой адрес базы задаётся через переменную окружения `APP_STORAGE__HOST: postgres`.

Внутренние сетевые имена сервисов (`postgres`, `slotify-backend`, `slotify-frontend`) автоматически резолвит встроенный DNS-сервер кластера Kubernetes (CoreDNS). Конфигурация и учётные данные передаются в контейнеры при запуске из объектов `Secret` через переменные окружения (с префиксами `APP_*` и `POSTGRES_*`).

## 5. Запуск приложения и всего-всего

В приложение используется Taskfile, поэтому я буду приводить таски из taskfile.yaml и пояснять их

1. Запуск кластера
```yaml
k8s:start:
    desc: Start 
    vars:
      CPUS: '{{.CPUS | default "8"}}'
      MEMORY: '{{.MEMORY | default "6144"}}'
    cmds:
      - minikube start --driver=docker --cpus={{.CPUS}} --memory={{.MEMORY}}
```
- *Запускается кластер на основе движка докера с указанными cpus и memory*
- *Если хотите запукасть с иными, попробуйте `task k8s:start CPUS=4 MEMORY=1024`, но учтите что ресурсы я настраивал под default значения*

2. После этого соберите образы и добавьте их в minikube
```yaml
k8s:load:
    desc: Build images and load them into minikube
    cmds:
      - task: docker:build
      - minikube image load --overwrite=true slotify-backend:{{.BACKEND_VERSION}}
      - minikube image load --overwrite=true slotify-frontend:{{.FRONTEND_VERSION}}
```
- *`docker:build` просто собирает образы*
- *Переменные `{{.BACKEND_VERSION}}` и `{{.FRONTEND_VERSION}}` являются глобальными и содержат в себе версию текущего релиза того или иного приложения*

3. Затем скачайте Traefik (Лично мне он нравится больше других обратных прокси)
```yaml
 k8s:traefik:
    desc: Install Traefik via Helm
    cmds:
      - helm repo add traefik https://traefik.github.io/charts
      - helm repo update
      - helm upgrade --install traefik traefik/traefik -n traefik --create-namespace
```

- *Мне особо нечего добавить, кроме того, что __с helm куда лучше, чем без него__*

5. После чего примените все манифесты и дождитесь поднятия всех подов
```yaml
k8s:apply:
    desc: Apply all manifests in order
    cmds:
      - kubectl apply -f k8s/namespace.yaml
      - kubectl apply -f k8s/secret.yaml
      - kubectl apply -f k8s/postgres.yaml
      - kubectl rollout status statefulset/postgres -n slotify --timeout=120s
      - kubectl apply -f k8s/backend.yaml
      - kubectl apply -f k8s/frontend.yaml
      - kubectl apply -f k8s/ingress.yaml
```
- *Тут всё довольно банально, `kubectl rollout status statefulset/postgres -n slotify --timeout=120s` ожидает запуска `postgres` и выводит стутус `partitioned roll out complete`*

6. И в конце создайте тунель для спокойной работы с traefik и CORS
```yaml
k8s:tunnel:
    desc: Run minikube tunnel (keep running, may need admin rights)
    cmds:
      - minikube tunnel
```

И вот после этого всё работает
